# Command — คำสั่งบน Serial Monitor ของทุกบอร์ด

เอกสารนี้รวมคำสั่งที่พิมพ์ได้จริงบน Serial Monitor ของทั้ง 6 บอร์ด ว่ามีอะไรบ้าง
พิมพ์ยังไง ตอบอะไรกลับมา และ**กับดักที่ทำให้พิมพ์แล้วได้ผลไม่ตรงที่คิด**

ทุกอย่างในนี้อ่านมาจากตัว parser จริง ไม่ได้ลอกจากข้อความ help
แต่ `printHelp()` ของทุกบอร์ดถูกอัปเดตให้ตรงกับเอกสารนี้แล้ว — แก้คำสั่งเมื่อไร
ต้องแก้ทั้ง parser, `printHelp()` และไฟล์นี้ให้ตรงกันทั้งสามที่

| บอร์ด | ไฟล์คอนโซล | เปิดมอนิเตอร์ |
|-------|-----------|--------------|
| master | [`src/master/console.cpp`](../src/master/console.cpp) | `pio device monitor -e master` |
| slave_hub | [`src/slave_hub/console.cpp`](../src/slave_hub/console.cpp) | `pio device monitor -e slave_hub` |
| slave_wheel | [`src/slave_wheel/console.cpp`](../src/slave_wheel/console.cpp) | `pio device monitor -e slave_wheel` |
| slave_arm | [`src/slave_arm/console.cpp`](../src/slave_arm/console.cpp) | `pio device monitor -e slave_arm` |
| slave_lift | [`src/slave_lift/console.cpp`](../src/slave_lift/console.cpp) | `pio device monitor -e slave_lift` |
| slave_button | *(ไม่มีคอนโซล)* | `pio device monitor -e slave_button` |

ทุก env ใช้ `monitor_speed = 115200` (ตั้งไว้ที่ `[env]` ใน `platformio.ini` ที่เดียว)

## พฤติกรรมร่วมที่ต้องรู้ก่อน

| | จบบรรทัดด้วย | ตัวพิมพ์เล็ก/ใหญ่ | ช่องว่างท้ายบรรทัด | ความยาวสูงสุด |
|---|---|---|---|---|
| master | `\n` หรือ `\r` | **แล้วแต่คำสั่ง** ดูหัวข้อกับดัก | ตัดให้ | 95 ตัวอักษร |
| slave_hub | `\n` (ทิ้ง `\r`) | พิมพ์เล็กได้หมด (แปลงเป็นใหญ่ก่อน) | **ไม่ตัด → คำสั่งพัง** | 47 ตัวอักษร |
| slave_wheel | **ไม่ต้องกด Enter** | ได้ทั้งสองแบบ | ข้ามให้ | — |
| slave_arm | `\n` หรือ `\r` | ได้ทั้งสองแบบ (แปลงเป็นใหญ่) | ตัดให้ | 40 ตัวอักษร |
| slave_lift | `\n` หรือ `\r` | ได้ทั้งสองแบบ | ตัดให้เฉพาะบางคำสั่ง | 47 ตัวอักษร |

master รับเฉพาะอักขระ ASCII ที่พิมพ์ได้ (32–126) อย่างอื่นทิ้งหมด
บรรทัดยาวเกินจะขึ้น `USB COMMAND TOO LONG` แล้วล้างบัฟเฟอร์ทิ้ง

## Master (Teensy 4.1)

parser ไล่เช็คจากบนลงล่างตามลำดับใน `processUsbLine()` ถ้าไม่ตรงสักอัน
จะตกไปที่ตัวจัดการแบบเก่าที่ดู **ตัวอักษรตัวสุดท้ายของบรรทัด** เป็นคำสั่ง

### ภารกิจ

| คำสั่ง | ทำอะไร |
|-------|--------|
| `M` | เริ่มภารกิจที่เลือกค้างไว้ |
| `M1` / `M2` / `M3` | เลือกแล้วเริ่มภารกิจนั้นทันที · **อ้างด้วยลำดับในทะเบียน** |
| `SEL 2` | เลือกภารกิจเฉย ๆ ไม่เริ่ม |
| `K0120011` | จำลองรหัสคีย์แพด — ผ่านตัวกรองและระบบโหวตชุดเดียวกับ `Serial3` |
| `A` | ยกเลิกภารกิจ (`USB ABORT`) · **ตัวใหญ่เท่านั้น** |

ทะเบียนมี 129 รายการ `Mn` รับได้ถึง `M129` — เลข 3 ตัวแรกคือ
`M1` = `exMission` · `M2` = `"MISSION 1"` (แดง) · `M3` = `"MISSION 2"` (ฟ้า)

รายละเอียดว่าแต่ละภารกิจทำอะไร ดู [mission.md](mission.md)
เปลี่ยนภารกิจระหว่างที่กำลังรันอยู่ไม่ได้ ต้อง `A` ก่อน

`K` ตามด้วยรหัสได้เลยไม่ต้องเว้นวรรค พิมพ์ตัวเล็ก `k` ก็ได้ · พิมพ์รัว ๆ 5 ครั้งใน 150 ms
จะจำลอง burst จริงของคีย์แพดได้ · ผลที่ได้จะขึ้นต้นด้วย `CONSOLE` แทน `SERIAL3`

### คีย์แพด (`Serial3`) — รับอย่างเดียว ไม่ได้พิมพ์เอง

| Mode | รูปแบบ | ยาว | ตัวอย่าง |
|------|--------|-----|---------|
| `0` | mode + field + line + box(4 หลัก) | 7 | `0120011` |
| `1` | mode + field + step + row + row | 5 | `11023` |

Mode 1 หลักที่ 5 ขึ้นกับ step — `step 0` = ทำทุก step เลือกได้ 2 แถว (หลัก 4 กับ 5
เป็นแถว ซ้ำแถวเดิมได้) ส่วน `step 2` / `step 3` เลือกแถวเดียวที่หลัก 4 แล้วหลัก 5 เป็น `0`

รหัสต้องผ่าน 4 ชั้นก่อนภารกิจจะเริ่ม แต่ละชั้นมี log ของตัวเอง:

| log | ความหมาย |
|-----|----------|
| *(เงียบ)* | บรรทัดว่าง — ถือเป็น noise ปกติ |
| `SERIAL3 BAD CODE (NOT DIGITS): [A4]` | มีตัวที่ไม่ใช่ 0-9 ปน — baud ผิดหรือบอร์ดส่ง label เดิมอยู่ |
| `SERIAL3 BAD CODE (LENGTH): [012001]` | ตัวอักษรหล่นหรือเกิน — สัญญาณรบกวน |
| `SERIAL3 BAD CODE (UNKNOWN MODE): [2130]` | หลักแรกไม่ใช่ 0 หรือ 1 |
| `SERIAL3 CODE TOO LONG - LINE DROPPED` | เกิน 31 ตัวไม่เจอตัวจบบรรทัด — framing พัง |
| `BUTTON VOTE FAILED - NO MAJORITY IN n FRAMES, m DIFFERENT CODES` | สายไม่นิ่ง หรือกดสองปุ่มติดกันใน 150 ms |
| `BUTTON CODE VOTED: [0120011] 5/5 FRAMES` | ผ่านหมด กำลังส่งต่อไปเริ่มภารกิจ |
| `UNKNOWN MISSION CODE: [0120011]` | **สายดี รหัสถูก** แต่ยังไม่มีภารกิจชื่อนี้ในทะเบียน |
| `MISSION ALREADY RUNNING` | มีภารกิจรันอยู่ ต้อง `A` หรือ SW_Yellow ก่อน |

บอร์ดคีย์แพดส่งตัวเลขล้วนที่ 115200 ตรงกับที่ Master รอแล้ว ถ้ายังเห็น
`BAD CODE (NOT DIGITS)` หรือขยะ แปลว่าบอร์ดยังไม่ได้แฟลชเฟิร์มแวร์ตัวใหม่
หรือสาย TX/RX สลับ / GND ไม่ร่วม — ทดสอบฝั่ง Master แยกได้ด้วยคำสั่ง `K`

### เคลื่อนที่

| คำสั่ง | ทำอะไร |
|-------|--------|
| `V,0.20,0.00,0.30` | ความเร็ว **local frame** — vx, vy (m/s), wz (rad/s) |
| `G,0.20,0.00,0.30` | ความเร็ว **global frame** (field-centric) พารามิเตอร์ชุดเดียวกัน |
| `V,0,0,0` / `G,0,0,0` | soft stop (ชะลอลงตาม ramp) |
| `P,1.00,0.50,90` | สั่งไปตำแหน่ง X, Y (m) และ Yaw (deg) ในระบบพิกัดโลก |
| `X` | ยกเลิก position control แล้วหยุด |
| `100a` | เดินหน้า 100 RPM |
| `100b` | ถอยหลัง |
| `100c` / `100d` | สไลด์ซ้าย / ขวา |
| `100e` / `100f` | หมุน CCW / CW |
| `s` | **หยุดฉุกเฉินทันที** (ถ้ากำลัง `HIGH START` อยู่ = ยกเลิก align แทน) |

ตัวเลขนำหน้าคือ RPM ของล้อ clamp ไว้ที่ 0–420 · คำสั่ง `a`–`f` จะตัด
position/velocity mode ทิ้งทันที

### lift (ผ่าน `Serial7`)

| คำสั่ง | ทำอะไร |
|-------|--------|
| `LP,1500,1500` | สั่งเสาหน้า/หลังเป็น pulse → ตอบ `LIFT_COMMAND_STARTED` |
| `LZ` | สั่ง lift homing → ตอบ `LIFT_HOME_STARTED` |

พิมพ์ `lz` `Lz` `lZ` ก็ได้ · timeout ของทั้งสองคำสั่งคือ 15 วินาที
(`LIFT_MOVE_TIMEOUT_MS`) · ฝั่ง master **ไม่ clamp** ค่า pulse — บอร์ด lift
เป็นคนตัดให้อยู่ใน 0–3800 / 0–3900 เอง

### แขนภายนอก (`Serial6`)

พิมพ์ได้สองสำนวน ให้ผลเหมือนกันเป๊ะ — สำนวนสั้นกับสำนวนโปรโตคอลตรง

| สำนวนสั้น | สำนวนโปรโตคอล | ทำอะไร |
|----------|---------------|--------|
| `AH` หรือ `ARM HOME` | `HOME` | homing แขน |
| `AB 90` | `B,90` | แกนล่างไป 90° |
| `AT 45` | `T,45` | แกนบนไป 45° |
| `AP 90 45` | `POS,90,45` | สั่งสองแกนพร้อมกัน |
| `AS` หรือ `ARM STATUS` | `STATUS` | ขอสถานะแขน |
| — | `STOP` | หยุดแขน + เคลียร์งานที่ค้าง |
| — | `CLEAR` | ล้าง FAULT ของแขน |

- ช่วงมุมที่บอร์ดแขนรับคือ 0–180° ทั้งสองแกน · timeout ปกติ 20 วินาที
- นำหน้าด้วย `CMD,` หรือ `CMD,<seq>,` ได้ master จะตัดทิ้งแล้วออก sequence ให้เอง
  (เอาไว้ paste บรรทัดที่ copy มาจาก log ได้เลย)

### hub (`Serial1`)

| คำสั่ง | ทำอะไร |
|-------|--------|
| `i` | โชว์สถานะ I/O + LiDAR + TFMini ทั้งชุดของ hub |
| `R1 ON` / `R1 OFF` | รีเลย์ 1–4 (`R2 1` / `R3 0` ก็ได้) · **รีเลย์ 4 = กริปเปอร์, ON = อ้า** |
| `ARM 40` | เซอร์โวแขนบน hub 0–80° |
| `SPIN 100` | เซอร์โวหมุนบน hub 0–133° |

### จัดตัวกับพื้นต่างระดับ

| คำสั่ง | ทำอะไร |
|-------|--------|
| `HIGH START` | ยกเสา → คลานเข้าทีละข้างจนลิมิตหน้าโดนทั้งคู่ → zero gyro → ถอย → ยกเสาแบบนุ่ม → จอด LiDAR |
| `HIGH START,3800,3900` | อันเดียวกัน แต่กำหนด pulse เสาหน้า/หลังหลังจัดตัวเสร็จเอง |
| `HIGH STOP` | ยกเลิก (`USB ABORT`) |

ค่า default คือ 3800 / 3900 · ถ้าหา LiDAR ไม่เจอจะถอยไปใช้ลำดับ TF2/TF1 แบบจับเวลาแทน
· กด `s` ระหว่างนี้ = ยกเลิก align

### สถานะและยูทิลิตี้

| คำสั่ง | พิมพ์อะไรออกมา |
|-------|----------------|
| `v` | `LINK=ONLINE TARGET=... PACKET good=.. bad=.. GYRO=ONLINE yaw=..` |
| `g` | `GYRO=ONLINE roll=.. pitch=.. yaw=..` |
| `i` | `HUB=ONLINE,inputMask=..,LDR1=..,Laser5=..,relayMask=..,TF1..TF4,lidarFound=..` |
| `o` | เปิด/ปิดการพิมพ์ `POSE,X=..,Y=..,YAW=..,SOURCE=GYRO` ต่อเนื่อง |
| `z` | ล้าง odometry ของ Teensy → `TEENSY ODOMETRY ZERO` |
| `r` | ตั้ง yaw ของ BNO085 เป็น 0 → `BNO085 YAW RESET TO 0 DEG` |
| `q` | ส่ง `Q` ไปบอร์ดล้อ ขอ feedback เดี๋ยวนี้ |
| `h` | help |

`POSE` เปิดอยู่ตั้งแต่บูต แต่จะพิมพ์ **เฉพาะตอน position control ทำงานและไม่ได้จอด LiDAR**
เท่านั้น ทุก 100 ms — ถ้าสั่ง `V,` แล้วไม่เห็น POSE ไม่ได้แปลว่าพัง

### ⚠ กับดักของ master

- **`A` ต้องเป็นตัวใหญ่เท่านั้น** — พิมพ์ `a` จะกลายเป็น "เดินหน้า 0 RPM" ไม่ใช่ยกเลิกภารกิจ
- **`M1` ไม่ใช่ `"MISSION 1"`** — `selectMission()` ทำ `selectedMission = n - 1` และ
  `exMission` อยู่หัวทะเบียน เลขจึงเลื่อนไป 1 ตำแหน่ง · ปุ่มบนหุ่นกับรหัสคีย์แพด
  อ้างด้วย **ชื่อ** จึงไม่โดนผลกระทบนี้
- **`K` ต้องติดกับรหัส** — `K 0120011` (มีเว้นวรรค) จะกลายเป็น `BAD CODE (NOT DIGITS)`
  เพราะช่องว่างถูกนับเป็นอักขระของรหัสด้วย
- **`STOP` = หยุดแขน ไม่ใช่หยุดหุ่น** — จะหยุดหุ่นต้อง `s` (ตัวเล็ก) หรือ `X`
- **`ARM 40` คือเซอร์โวบน hub** ส่วนแขนจริง 2 แกนใช้ `AB` / `AT` / `AP`
- ตัวจัดการแบบเก่าอ่าน **ตัวอักษรตัวสุดท้าย** ของบรรทัด — พิมพ์ `120 rpm` จะโดนอ่านเป็น `m`
  แต่พิมพ์ `120 forward` จะกลายเป็น `d` = **สไลด์ขวา 120 RPM จริง ๆ** ระวังตอนพิมพ์เล่น
- เรื่องตัวพิมพ์เล็ก/ใหญ่แบ่งเป็นสองพวก:
  - **คำล้วน ๆ ไม่สนตัวพิมพ์** — `HOME` `STOP` `CLEAR` `STATUS` `AH` `AS` `ARM HOME`
    `ARM STATUS` `HIGH START` `HIGH STOP` `LZ` `M` `X` `i` พิมพ์แบบไหนก็ได้
  - **คำสั่งที่มีพารามิเตอร์ ต้องใหญ่ล้วนหรือเล็กล้วน** — `AB 90` / `ab 90` ได้
    แต่ `Ab 90` ไม่ได้ · ใช้กับ `AB` `AT` `AP` `POS,` `B,` `T,` `SEL` `R1 ON` `ARM` `SPIN`
    `LP,` `P,` `V,` `G,` เหมือนกันหมด
- ช่องว่างท้ายบรรทัด master ตัดให้แล้ว (`HIGH START ` ใช้ได้) แต่บอร์ดอื่นไม่ตัด

## slave_hub (Teensy 4.1)

**parser ตัวเดียวกันรับทั้ง USB และ `Serial1` จาก Master** — ทุกคำสั่งในตารางนี้
Master ก็ส่งมาได้ และคำสั่งที่มาจาก Master จะได้ `ACK,<คำสั่ง>` ตอบกลับ
(ยกเว้นตระกูล `GET ...` ที่ตอบเป็นข้อมูลอยู่แล้ว) ถ้าไม่รู้จักจะตอบ `ERR,UNKNOWN,<คำสั่ง>`

| คำสั่ง | ทำอะไร |
|-------|--------|
| `R1 ON` / `R1 OFF` … `R4` | รีเลย์ 1–4 (LOW = ON ที่ระดับขา) · **R4 = กริปเปอร์, ON = อ้า** |
| `ALL ON` / `ALL OFF` | รีเลย์ทั้งหมด |
| `STOP` | **= `ALL OFF`** ปิดรีเลย์ทุกตัว |
| `ARM 0..80` | เซอร์โวแขน |
| `SPIN 0..133` | เซอร์โวหมุน |
| `INPUT` / `OUTPUT` / `STATUS` | โชว์อินพุต / เอาต์พุต / ทั้งคู่ |
| `LIDAR ON` / `LIDAR OFF` | เปิด/ปิดรายงาน LiDAR ออก USB (= โหมด `M2` / `M0`) |
| `LIDAR STATUS` | พิมพ์ผลตรวจจับหนึ่งครั้ง |
| `LIDAR RESET` หรือ `R` | ล้างฟิลเตอร์ตรวจจับ |
| `M0` / `M1` / `M2` / `M3` | ปิด / สรุป / สรุป+แถบกล่อง / จุดสแกนเป็น CSV |
| `MODE BOX` หรือ `BOX` | โหมดหากล่อง (ระยะ/ศูนย์กลาง/มุม) |
| `MODE WALL` หรือ `WALL` | โหมดหาระนาบกำแพงด้านหน้า |
| `MODE?` หรือ `MODE` | ถามโหมดปัจจุบัน |
| `D450` | ระยะเป้าหมายสำหรับให้คะแนน 100–2000 mm (ค่าเริ่ม 450) |
| `A0.45` | filter alpha 0.01–1.00 (ค่าเริ่ม 0.45) |
| `T250` | คาบการพิมพ์ 50–5000 ms (ค่าเริ่ม 50) |
| `GET LIDAR` / `GET IO` / `GET SERVO` / `GET TFMINI` / `GET STATUS` | ยิงแพ็กเก็ตให้ Master หนึ่งครั้ง |
| `STREAM ON` / `STREAM OFF` | เปิด/ปิดสตรีมแพ็กเก็ตเต็มไปหา Master (20 Hz) |
| `HELP` หรือ `M?` | help |

โหมด `M3` พิมพ์เป็นบล็อก `SCAN_BEGIN` → `P,<มุม>,<ระยะ>,<x>,<y>` … → `SCAN_END`
เอาไป plot ต่อได้

### ⚠ กับดักของ hub

- **`STOP` ที่นี่ = ปิดรีเลย์ทั้งหมด** ไม่เกี่ยวกับการหยุดหุ่น
- **`M1`/`M2`/`M3` ที่นี่คือโหมดมอนิเตอร์** ไม่ใช่ภารกิจ — พิมพ์ผิดบอร์ดแล้วงงได้ง่ายมาก
- **ไม่ตัดช่องว่างท้ายบรรทัด** — `"R1 ON "` จะกลายเป็น `UNKNOWN COMMAND`
- `STREAM ON` เปิดอยู่แล้วตั้งแต่บูต (ทั้งค่า default ของ hub เองและ Master สั่งซ้ำตอน setup)
  ถ้าสั่ง `STREAM OFF` เล่น ฝั่ง Master จะมองว่า hub offline ภายใน 300 ms
  แล้ว step ที่พึ่ง hub จะ fail ทั้งภารกิจ

## slave_wheel (Blackpill F411CE)

**คอนโซลนี้ไม่ต้องกด Enter** — ตัวเลขจะถูกสะสมไว้ก่อน พอเจอตัวอักษรจะทำงานทันที

| คำสั่ง | ทำอะไร |
|-------|--------|
| `100a` | เดินหน้า 100 RPM |
| `100b` | ถอยหลัง |
| `100c` / `100d` | สไลด์ซ้าย / ขวา |
| `s` | หยุด |
| `v` | พิมพ์ `FL:SP=..,RPM=..,PWM=..,C=..` ครบ 4 ล้อ |
| `z` | ล้าง encoder ทั้ง 4 ตัว + reset ฟิลเตอร์ RPM |
| `h` | help |

คำสั่งฝั่งลิงก์ `Serial1` (Master ส่งมา ไม่ได้พิมพ์เอง):
`T,<FL>,<FR>,<RL>,<RR>` (เว้นวรรคแทน comma ก็ได้) · `S` · `Q`
ถ้าไม่มี `T,` ใหม่เข้ามาภายใน 500 ms บอร์ดจะหยุดเองแล้วตอบ `E,TIMEOUT_STOP`

### ⚠ กับดักของ wheel

- **พิมพ์ตัวอักษรอะไรก็ตามจะตัดสิทธิ์ Master ทันที** (`serial1ControlActive = false`)
  Master ต้องส่ง `T,...` เข้ามาใหม่ถึงจะคุมได้อีก — เจอบ่อยตอนแอบพิมพ์ `v` ดูสถานะระหว่างรันภารกิจ
- **`z` ทำ odometry ของ Master เพี้ยนทั้งชุด** เพราะ Master คำนวณระยะจาก
  *ผลต่าง* ของ count ที่ส่งมา การ zero กลางทางจะกลายเป็น delta ก้อนใหญ่ก้อนเดียว
  ถ้าเผลอกดไปแล้ว ให้สั่ง `z` ที่ฝั่ง Master ตามด้วยเพื่อล้างพิกัดใหม่
- บอร์ดพิมพ์สถานะเองทุก 100 ms อยู่แล้ว มอนิเตอร์จะวิ่งตลอดเวลา เป็นเรื่องปกติ

## slave_arm (Blackpill F411CE)

| คำสั่ง | ทำอะไร |
|-------|--------|
| `HOME` | homing: Bottom ชนหน้า = 0 → Top ชนหน้า = 0 → Top ไป 100° |
| `B90` / `B45.5` | แกนล่างไปองศาที่สั่ง (0–180) |
| `T90` / `T45.5` | แกนบนไปองศาที่สั่ง (0–180) |
| `BPWM 120` | ทดสอบ PWM แกนล่าง −255..255 (ลบ = FRONT, บวก = BACK) |
| `TPWM -80` | ทดสอบ PWM แกนบน −255..255 (บวก = FRONT, ลบ = BACK) |
| `LIMITS` หรือ `L` | อ่านลิมิตทั้ง 4 ตัวครั้งเดียว (`PRESSED` / `OPEN`) |
| `STREAM ON` | พิมพ์ลิมิตต่อเนื่องทุก 200 ms |
| `STREAM OFF` | กลับไปพิมพ์ `STATUS` ทุก 500 ms ตามปกติ |
| `STOP` หรือ `X` | หยุดมอเตอร์ทั้งสองแกน |
| `STATUS` หรือ `?` | encoder, องศา, เป้าหมาย, ลิมิต, state |
| `CLEAR` | ล้าง FAULT กลับไป IDLE |
| `HELP` | help |

บอร์ดพิมพ์ `STATUS` ให้เองทุก 500 ms · ถ้าเปิด `STREAM ON` จะสลับไปพิมพ์ลิมิต
ทุก 200 ms แทน (ไม่พิมพ์ทั้งสองอย่างพร้อมกัน)

### ⚠ กับดักของ arm

- **สำนวนของคอนโซลกับของลิงก์ไม่เหมือนกัน** — ที่นี่ใช้ `B90` (ไม่มี comma)
  ส่วน Master ส่งมาทาง `Serial1` เป็น CSV `CMD,<seq>,B,90` คนละ parser กันคนละไฟล์
- **พิมพ์ `B,90` แบบสำนวน Master ที่บอร์ดนี้ = สั่งไป 0°** เพราะ `,90` แปลงเป็นตัวเลขได้ 0
  แล้วแขนจะวิ่งไปสุดจริง ๆ โดยไม่มี error บอก
- `STREAM ON` ที่นี่ = สตรีมลิมิตออก USB ส่วน `STREAM ON` ที่ hub = สตรีมแพ็กเก็ตไป Master

## slave_lift (Blackpill F411CE)

**คำสั่งชุดนี้ใช้ parser ตัวเดียวกับที่รับจาก Master ทาง `Serial1`** — พิมพ์อะไรได้
Master ก็ส่งอันนั้นได้

| คำสั่ง | ทำอะไร |
|-------|--------|
| `LP,3800,3900` | สั่งตำแหน่งเสาหน้า/หลังเป็น pulse (clamp 0–3800 / 0–3900) |
| `LZ` หรือ `HOME` | homing ลงไปชนลิมิตล่างแล้ว zero encoder ทั้งสองเสา |
| `S` | หยุดมอเตอร์ |
| `Z` | หยุดพร้อม zero encoder + เป้าหมายทันที |
| `POSE` | ตำแหน่ง mm, pulse, เป้าหมาย, setpoint, PWM, ลิมิตทั้ง 4 |
| `LIMIT` | อ่านเฉพาะลิมิต `FT=.. FB=.. BT=.. BB=..` |
| `PID` | โชว์ gain ปัจจุบันของทั้งสองเสา |
| `5300p` `4000i` `0d` | ตั้ง gain **ทั้งสองเสาพร้อมกัน** |
| `5300fp` `2300bp` | ตั้งแยกเสา — `f*` = front, `b*` = back, ตามด้วย `p`/`i`/`d` |

- **gain พิมพ์เป็นจำนวนเต็ม ×1000** — `5300p` คือ Kp = 5.300 · พิมพ์ `5.3p`
  จะไม่ผ่านและขึ้น `ERR:` (ตั้งใจให้เป็นแบบนี้ จะได้ไม่ต้องพิมพ์จุดบนมือถือ)
- ตั้ง gain ทุกครั้งจะ `resetControllers()` ล้าง error สะสมให้ด้วย
- stroke จริง 400 mm ต่อเสา `POSE` แปลง pulse เป็น mm ให้แล้วในช่อง `Fmm` / `Bmm`

บอร์ดพิมพ์ `POSE` ให้เองทุก 500 ms และส่ง `LIFT_POS,<front>,<back>` ไป Master ทุก 20 ms
ข้อความที่ส่งให้ Master จะขึ้นบน USB ด้วยโดยมี `[TEENSY]` นำหน้า

บอร์ดนี้**ไม่มีคำสั่ง `HELP`** — help เต็มพิมพ์ให้ครั้งเดียวตอนบูต ถ้าพิมพ์อะไรไม่ถูก
จะได้บรรทัด `ERR: LP,f,b | LZ | S | POSE | PID | p/i/d` เป็น help ย่อแทน

### ⚠ กับดักของ lift

- **`Z` อันตรายกว่าที่คิด** — มัน zero encoder ที่ตำแหน่งไหนก็ได้ ถ้าเสาไม่ได้อยู่ล่างสุด
  ระบบจะเชื่อว่าจุดนั้นคือ 0 แล้วยอมให้สั่งลงต่ออีก 3800 pulse จนชนกลไก
  ถ้าจะรีเซ็ตให้ถูกต้องใช้ `LZ` เสมอ
- `S` หยุดมอเตอร์เฉย ๆ ไม่ล้างเป้าหมาย — คำสั่งถัดไปที่เข้า PID จะดึงกลับไปหาเป้าหมายเดิม

## slave_button (Blue Pill F103C8)

บอร์ดนี้**ไม่รับคำสั่งใด ๆ** เปิดมอนิเตอร์ได้อย่างเดียวเพื่อดู log

```
=== F103 Mission Keypad ===
Enter code via keypad, press 16=START to send on Serial1.
This board takes no console commands; it only reports codes.
[KEY] Mission keypad init OK
[KEY] #13 page=2
[KEY] #4 page=3
[SEND] 10012 x5
```

`[KEY] #n page=p` ออกทุกครั้งที่กดปุ่ม (n = เลขปุ่ม 1..16, p = หน้าเมนูหลังกด
โดย 0=MODE 1=FIELD 2=SEL3 3=SEL4 4=RECHECK 5=SENT)
ส่วน `[SEND] <รหัส> x5` ออกเฉพาะตอนกด 16 = START ที่หน้า RECHECK เท่านั้น —
ส่งซ้ำ 5 บรรทัด ห่างกัน 20 ms ออก `Serial1` ไปหา Master

log พวกนี้ออกทาง **USB CDC** ไม่ใช่สายที่ต่อ Master — `platformio.ini` เซ็ต
`ENABLE_HWSERIAL1` + `PIN_SERIAL1_TX=PA9` แยก `Serial1` ออกจาก `Serial` ให้แล้ว
เปิดมอนิเตอร์ดูได้โดยไม่มีข้อความ debug หลุดลงลิงก์

| | ค่า |
|---|---|
| baud ทั้งสองฝั่ง | 115200 (`F103_SERIAL_BAUD` = `BUTTON_BAUD`) |
| payload | ตัวเลขล้วน 5 หรือ 7 หลัก + `\n` |
| รหัสที่กดได้ | 126 อัน ตรงกับทะเบียนฝั่ง Master แบบ 1:1 |

ทดสอบฝั่ง Master แยกจากบอร์ดนี้ได้ด้วยคำสั่ง `K<รหัส>` บนคอนโซล master
ซึ่งวิ่งผ่านตัวกรองและระบบโหวตชุดเดียวกันเป๊ะ

## เพิ่มคำสั่งใหม่

ทุกบอร์ดเพิ่มที่ `console.cpp` ของตัวเอง แล้วอัปเดตให้ครบทั้ง 3 ที่:
parser → `printHelp()` ของบอร์ดนั้น → ตารางในไฟล์นี้

- **master** — แทรก `if` ก้อนใหม่ใน `processUsbLine()` **ก่อน** บรรทัดสุดท้ายที่เรียก
  `executeLegacyUsbCommand(line)` ไม่งั้นคำสั่งจะถูกตัวจัดการแบบเก่าอ่าน
  "ตัวอักษรตัวสุดท้าย" ไปก่อน
- **slave_hub / slave_lift** — คำสั่งที่เพิ่มจะใช้ได้ทั้งจาก USB และจาก Master
  ทันทีเพราะใช้ parser ร่วมกัน ถ้าไม่อยากให้ Master เรียกได้ต้องเช็ค `fromMaster` เอง
  (hub) หรือแยก entry point เอง (lift)
- **slave_arm** — เพิ่มที่คอนโซลอย่างเดียวจะยังสั่งจาก Master ไม่ได้
  ต้องไปเพิ่ม `case` ใน `master_link.cpp` ของโปรโตคอล CSV ด้วยอีกที่
- **slave_wheel** — คำสั่งเป็นตัวอักษรเดี่ยว เพิ่ม `else if` ใน `executeSimpleCommand()`
  ตัวเลขที่พิมพ์นำหน้าถูกแปลงเป็น `rpm` มาให้แล้ว · จำไว้ว่าคำสั่งจากคอนโซล
  ปิด `serial1ControlActive` ทุกครั้ง
